GhostMesh Documentation

GhostMesh is a zero-configuration, peer-to-peer encrypted mesh overlay network built with Rust and Tauri v2. It connects your devices directly over UDP across domestic NATs and firewalls without relying on any centralized data relay servers.

Quick Start

Option A: Instant execution via npx (Zero install)

You can run GhostMesh directly in any terminal using Node.js without needing to install Rust or Cargo:

# On Machine A (Host)
npx ghostmesh-cli invite

# On Machine B (Guest)
npx ghostmesh-cli join <ticket>

Option B: Building from Source

Clone the repository and build the workspace with Cargo:

git clone https://github.com/NeyorDEV/ghostmesh.git
cd ghostmesh
cargo build --release

# Run CLI
cargo run -p ghost-cli -- invite

# Run GUI
cargo run -p ghostmesh-gui

Architecture Overview

Zero Central Relay Principle: Unlike traditional VPNs (where all traffic flows through a single centralized server bottleneck), GhostMesh only uses public STUN servers for discovery. All actual data frames travel directly point-to-point.

1. Binary Wire Format

Every UDP packet in GhostMesh follows a compact binary layout with a fixed 43-byte header:

[0..2]   Magic Bytes (0x47, 0x4D -> "GM")
[2]      Packet Type (0x01: STUN_PROBE, 0x02: HANDSHAKE_INIT, 0x03: HANDSHAKE_RESP, 0x04: DATA, 0x05: KEEP_ALIVE)
[3..19]  Destination Node ID (16 bytes)
[19..35] Source Node ID (16 bytes)
[35..43] Sequence Number / Nonce (8 bytes Big-Endian)
[43..]   Encrypted Payload + Poly1305 Authentication Tag (16 bytes)

2. Noise Protocol Cryptography

Security is enforced via mutual authentication using the Noise_XX_25519_ChaChaPoly_BLAKE2s pattern:

  • Key Exchange: Ephemeral & static Curve25519 keypairs.
  • Cipher: ChaCha20-Poly1305 authenticated symmetric encryption (AEAD).
  • Hash: BLAKE2s for transcript authentication and key derivation.

3. STUN & Automated UPnP Traversal

To bypass domestic routers and Carrier-Grade NAT (CGNAT):

  1. Both nodes query public STUN servers (stun.l.google.com:19302) to discover reflexive IP:Port mappings.
  2. Automated UPnP: GhostMesh automatically negotiates port 4242 UDP mapping on domestic Internet boxes via IGD, eliminating manual router port forwarding.
  3. When pairing, nodes exchange synchronized UDP hole-punching probes to maintain open firewall state tables.
  4. Background keep-alives every 10 seconds keep NAT port mappings open indefinitely.

4. Multi-Hop Mesh Routing

GhostMesh nodes act as autonomous transit routers. If Node A cannot directly reach Node C due to an asymmetric firewall, but both A and C have an active link with Node B, Node B seamlessly and securely forwards end-to-end encrypted packets between A and C without being able to decrypt the payload.

5. HTTPS / TCP Fallback Relay

When operating inside enterprise or university networks that strictly filter all outbound UDP traffic, GhostMesh automatically activates its fallback relay tunnel over standard HTTPS port 443, ensuring 100% connectivity even through the most restrictive firewalls.

6. Virtual Network Adapter (Wintun)

GhostMesh instantiates a virtual Layer 3 network interface (ghost0) powered by Wintun on Windows. It assigns an IP address in the private mesh subnet (10.42.0.0/16), allowing system tools like ping, SSH, and file transfers to traverse the P2P mesh as if connected over a local LAN.

Desktop Dashboard (GUI)

The desktop application provides a modern dark glassmorphism dashboard built with Tauri v2 and native Rust bindings:

  • Live Status Indicators: Real-time display of local virtual IP (10.42.X.Y/16), public STUN endpoint, and cryptographic Node ID.
  • One-Click Invite Generator: Create encrypted base64 gm1_... invitation tickets containing your Curve25519 public key and reflexive UDP endpoint.
  • Active Mesh Links Table: View active peer endpoints, real-time RTT round-trip latency, and connection states (Connected / Disconnected).
  • System Tray Minimization: Closes cleanly to the Windows system tray and runs silently in the background without terminal prompts.

QR Code Instant Pairing

GhostMesh includes native vector SVG QR Code generation. When inviting a peer, simply display the QR Code directly from the Invitation modal. Any companion device or smartphone can scan the code to instantly extract the pairing ticket without copying long text strings.

GhostDrop - Built-in P2P File Transfer

GhostDrop is GhostMesh's native all-in-one file transfer engine. Unlike cloud storage or local-only utilities like AirDrop, GhostDrop transfers files directly peer-to-peer across the internet at the maximum physical speed of your connection:

All-In-One Convenience: Zero third-party tools needed. No need to configure Windows SMB shares, open firewall ports, or install LocalSend. GhostDrop runs directly inside the GhostMesh interface and CLI.

How it Works

  1. Select a Connected Peer: Choose from the active peers listed in your mesh network.
  2. Pick Any File: Drag and drop or browse for any file (archives, video files, datasets). There is no file size limit.
  3. Stream with GhostDrop: High-throughput asynchronous streaming sends encrypted 128 KB chunks directly to the recipient over port 4243.
  4. Auto-Save to Transfers: The receiving peer automatically saves files to Downloads/GhostMesh-Transfers/ and displays real-time MB/s throughput.

GhostSync - Continuous Folder Synchronization

GhostSync provides real-time folder synchronization similar to Syncthing, embedded directly into your GhostMesh daemon:

  • Zero Configuration: Select a local folder to watch.
  • Automated Change Detection: GhostSync periodically tracks filesystem changes and diffs file manifests.
  • Peer Sync: Modifications are automatically synchronized in the background to connected mesh peers without user intervention.

CLI Reference

ghostmesh keygen                    # Generate a fresh cryptographic identity keypair
ghostmesh discover                  # Query STUN to resolve local NAT endpoint
ghostmesh invite [--port 4242] [--ip 10.42.0.1] # Generate ticket and wait for peer
ghostmesh join <ticket> [--ip 10.42.0.2]       # Join peer and negotiate UDP hole-punching
ghostmesh send <target> <file>      # Send file via GhostDrop P2P high-speed streaming
ghostmesh receive [--dir <path>]    # Receive files via GhostDrop listener daemon
ghostmesh up [--port 4242] [--ip 10.42.0.1]    # Run standalone background node

Firewalls & Troubleshooting

P2P direct connections rely on UDP traversal. If your nodes fail to connect, review the typical scenarios below:

Corporate / Work Firewalls (STUN 0.0.0.0:4242): If your node shows 0.0.0.0:4242, your local corporate or campus network blocks outbound UDP traffic or STUN discovery. Pure P2P requires UDP communication.

1. Connecting Home to Work

  • Work / University Firewalls: Most enterprise firewalls strictly drop unsolicited or arbitrary outbound UDP packets. To test from work, switch your machine to a mobile 4G/5G Wi-Fi hotspot where UDP and STUN are unrestricted.
  • Residential Router Port Forwarding: At home, routers (Freebox, Livebox, SFR, Bouygues) drop unexpected inbound UDP. You can forward UDP port 4242 directly to your home PC's local IP in your box admin panel (192.168.1.1).

2. NAT Types & Symmetric NAT

UDP hole-punching succeeds with Cone NATs (Full Cone, Restricted Cone, Port-Restricted Cone). When a network uses Symmetric NAT (common in enterprise networks), external ports change randomly for each destination. For symmetric networks, a relay fallback (DERP / TURN) or port forwarding is required.
